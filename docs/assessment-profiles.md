# 测评版本、旧档案与续答保护（v1.16.0）

本次将学术题库版本与规划/性格版本分开。学术仍为 `2026.10`，它不能代表两代规划与性格题目相同。新测评保留互动游戏与30题特质功能；旧档案继续使用原14道规划、24道数字量表和原报告引擎。

| profile | 规划 / 性格 | 当前支持 |
|---|---|---|
| `legacy-2026.10` | 14题、13必答 / 24个数字或null | 原义续答、报告/PDF、JSON备份、旧CSV、既有账号及授权流程 |
| `games-traits-v1` | 13题、12必答 / 30个对象或null | 本机续答、报告/PDF、顾问本机编辑、JSON备份；云端及汇总后续适配 |

## 第一次打开已有进度

合法旧进度和已发行但没有profile标记的新进度，打开后均先保护原始JSON。确认之前，导航、自动保存、刷新或离开不会改写浏览器里的原始字节。页面可在内存中查看或作答；请先点击「下载原始JSON备份」，再确认按识别出的原版本继续并允许本机保存。

旧模式显示旧14道规划与24道数字量表，保留原自由科目、组队规模和时间偏好，不把24个数字按位置解释成30项新题。空白、部分、中立及带顾问修改的报告也按旧引擎生成。原始JSON下载是恢复线索；需要保留报告版式时另存PDF。

未知版本、混合答案或带 `mbti.legacy` 的已转换资料不能可靠恢复题目对应关系，页面只提供原始导出和明确开始新版，不给这些答案生成新的特质结论。「开始新版」需确认并检查原始进度未被另一标签改动。重新测评会替换当前续答；已归档报告仍保留。读取存储失败时锁住写入，可在本次页面作答，但不能假称已读取/备份原进度，需保留页面并处理存储权限。

## 备份与往返

- 纯旧报告仍导出 `bic-report-library` version 1；原记录不添加profile字段，原答案、null、短数组、自由科目、编号/日期、顾问history/actor均保留。
- 新归档在记录顶层写 `assessmentProfile: "games-traits-v1"`，备份容器为version 2，可包含旧记录。归档state仍是info/academic/plan/mbti四键。
- 已发行的无标记新形状可从version 1读取，读取时不悄改记录；明确重新归档后才写新版标记。version 1不能承载带新版标记的记录。
- 新旧同一编号不能跨profile覆盖；原100份、2M UTF-16、历史200条、配额/损坏/整批校验与失败保留规则继续有效。非法JSON值不会先转成null再接受。
- 旧17列CSV只处理纯旧库；新或混合库明确停止CSV并提示使用JSON。新CSV口径未在本阶段增加，JSON是完整备份。

## 账号、分享和统计边界

现有后端ArchiveRecord、家长摘要/批注、顾问摘要v1/v2/v3、可选文案草稿、本地统计及成绩配对仍采用旧合同。新profile在发送云归档或进入旧投影前明确拒绝；不会截断30题、丢掉游戏、把派生专业字段当作原来明确回答的12类兴趣。当前账号改密仍可独立使用。

旧云报告可按原义打开和继续；双方启用/角色、单报告权限、期限/撤销、源修订、CSRF/CAS不变。schema5/API2，无新表或迁移，也没有访问公司真实学生浏览器或数据库。下一阶段先单独实现新版严格云归档，再逐项定义新分享/摘要合同，旧格式和权限不会自动扩展。
