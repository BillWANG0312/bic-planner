## 必须先分清两代测评

学术 `bankVersion=2026.10` 仍表示同一60题学术题库，不能据此判定规划和性格答案相同。

| 使用范围 | `legacy-2026.10` | `games-traits-v1` |
|---|---|---|
| 规划 / 性格 | 14题、13必答 / 24个数字或null | 13题、12必答 / 30个对象或null |
| 本机续答、报告/PDF、顾问本机文字编辑 | 支持原含义 | 支持游戏/特质含义 |
| 完整JSON备份 | 纯旧库保持v1与原记录 | 明确标记的新记录使用v2，可混合旧记录 |
| 本机CSV | 纯旧库原17列 | 尚未定义，明确提示改用JSON |
| 云归档、家长分享/批注、顾问协作与摘要、文案草稿 | 原严格合同支持 | 尚未适配，明确拒绝 |
| 本地统计、后续成绩配对 | 原严格合同支持 | 尚未适配，明确拒绝 |

旧续答/无标记新版首次打开时先下载原始JSON，再明确继续原版或开始新版；确认前不会自动覆盖原字节。未知、混合或带 `mbti.legacy` 的已转换资料保留恢复入口，不伪造原问卷恢复或特质结论。不要手改备份、删标记、截断30题，或把旧24个数字按索引包装成新题答案。

旧 `preferredMajor` 是最多2选的明确兴趣回答；新版 `majorBoard` 的派生/兼容字段不代表相同含义。旧摘要v1/v2/v3与本地统计格式不能直接套用新版数据。顾问CSV含姓名/编号，统计也不承诺充分匿名；题库百分比、推荐排序均不是正式成绩、录取概率或已校准量表。

## 接手后按什么顺序改

1. **先审阅本轮架构基础并复现。** PR #8已由所有者合并，下一阶段从更新main的新分支推进。本轮补统一profile合同、操作策略和认证能力元数据；新版业务操作仍关闭。用虚构资料核对合同、投影拒绝、旧授权与原值保护，再接入下一段云归档。
2. **单独适配新版严格云归档。** 新建可辨认的模型及合同快照，涵盖游戏格、固定枚举、30个value/ms对象、缺答和容量。定义前后端能力/版本检查，主动选择并预览确认后才能创建、读取、修订更新和本机打开。验收需覆盖新旧往返不丢数据、旧端明确拒绝新版、跨账号/源变化/CAS/配额/结果未知，以及旧工作流不回归。先不扩展分享或摘要。
3. **再逐项适配新版协作。** 分别定义家长摘要、批注范围、顾问只读/文字编辑和文案上下文；每项单独验收期限、撤销、禁用、修订、审计及私密字段。新云归档能保存不代表旧授权能自动读取或编辑新版，原只读权限不可自动扩权。
4. **最后版本化新版汇总与校准准备。** 先定义完成度、学科表现、学生明确选择与规则派生的字段/分母，再加入顾问CSV、本地统计及成绩配对。保留旧格式和指纹，验证缺答、0、部分报告、小单元/补集和导出前后快照变化。没有真实可比样本不能拟合阈值或宣称预测有效。

每一段先加有意义的失败用例，再实现、独立审查和运行对应回归；一次交付一个可验证模块。管理员找回/身份复核、组织管理和公开注册尚未实现，待明确业务流程后独立排期。规则推荐跨报告扩展也不默认加入当前学生自选摘要。

## 上线仍需团队提供什么

- 公司批准的服务器、同源HTTPS/反代、部署账号、数据库/备份权限、日志脱敏，以及可信代理/共享限流/容量验证。当前单进程内限流不能直接当作多worker生产方案。
- 题库和量表的教师/专业复核；院校资料后续按申请年份更新。已有来源核验不能替代教学或心理测量验证。
- 若启用真实AI：批准供应商、数据处理范围、费用和用户确认文案后，再实现真实适配器；当前模拟不能称真实AI接入。
- 若做真实校准：明确样本来源、独立性、考试可比性、授权及外部验证计划；目前没有真实校准、常模或A/B完成率/分享率证据。

数据库当前schema5、健康API2。任何新版入口或账号CLI可能触发已知版本迁移，运行前先停服务，在实际网站根目录之外做私有一致备份并保存匹配源码；未知结构应拒绝，失败回滚，回退时保留新库并恢复匹配旧备份，不手改user_version。具体步骤见 [升级与回退](advisor-edit.md#schema5升级与回退)。
