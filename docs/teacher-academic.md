# 显式可选的学科表现摘要v2（v1.13.0）

顾问完成度清单默认仍为格式v1、21列及原文件名。只有在`teacher-summary.html`明确勾选「附加同版题库学科表现」后才请求v2、预览并导出29列。所用账号、逐份选择1–20个有效完整报告只读授权和确认前后复查沿用 [完成度清单](teacher-summary.md)；编辑授权、家长链接/批注和advisor角色本身不扩权。

## 操作与含义

主动连接/登录/刷新后逐份选择报告，再决定是否勾选v2。切换模式会清旧预览，不能直接把v1预览当作v2下载。预览显示四科学科表现及当前规则版本、完整指纹和未校准说明；核对后再确认保存。v2文件名为`bic-teacher-academic-v2.csv`；取消不下载，取消v2后回到原v1格式。

每科15题等权，只有这一科全部有效作答才显示`round(答对题数/15×100)`的整数百分比；完整科目0%是有效结果。未完整科目API为null，表格/CSV显示「未完整」，不将缺答解释为0分。整份报告仍为草稿时，其中已完成的科目也可显示题库表现；不要求规划或性格全部完成。

这是当前同版本题库规则重算的答对比例，**不是正式学校成绩、A-Level预测、学习增长、录取概率或真实样本校准**。题目与难度仍待教师审校，系统没有新常模、阈值拟合或验证历史规则。CSV含姓名/编号，属于可识别学生的私密校内资料，不能称匿名或公开数据。

v2在原21列后追加四科「题库表现（仅完整，%）」及评分规则版本、规则指纹、规则依据、校准状态，共29列。规则依据固定「当前同版规则重算」，校准状态「未校准」。纯文本预览和CSV复用同一字段映射；BOM、CRLF、引号/换行与公式前缀保护保持，内部表格可左右滚动，手机页面不横向溢出。

## 新鲜度和权限

模式、所选ID、页面账号、期限及完整payload一起绑定预览。导出前和确认后都用同一模式重新核对整批授权/源修订/规则指纹；服务端静默改成另一版本、公开规则元数据不一致、读取失败、到期或身份变化均停止旧导出，不自动重试、覆盖或降级为v1。即使程序在确认框或最终请求期间改变选项，也会拒绝旧预览。

到期、断开/注销/离开或换账号清名单和CSV，迟到响应不能恢复。最后核对后已经下载/复制的内容不能收回。所有修改只为摘要响应和内存预览；原答卷、报告建议/审计、数据库修订和阈值不变。没有新表、导出缓存、浏览器存储、自动上传、轮询或外部服务请求。

## API

`POST /api/teacher-summaries`增加可选布尔`academic`。缺省或false仍是原`{grant_ids}`请求的v1结果；true明确请求v2。数字、字符串、null及额外字段拒绝422。Origin/CSRF、页面身份和单JOIN整批权限/版本校验保持；只读授权失效仍整批404。

v2沿用format，version为2，顶层增加scoring；每个report只增加performance四行`{key,complete,pct}`。complete必须对应该科学术已答15；不完整pct只能null，完整pct只取15题等权的16个可能整数值之一，0有效。摘要不向页面发送原始答案、答案键、逐题正误、未完整科正确数或完整审计。

scoring精确六键：bank_version、rule_version、rule_fingerprint、basis、incomplete_policy、calibration。分别为当前题库、`academic-pct-v1`、SHA256指纹、`current_local_rules_recomputed`、`not_scored`和`not_calibrated`。浏览器必须与随页面部署的安全公开元数据逐字一致；不一致拒绝v2，前后端需一起更新。默认v1不依赖可选计分快照。

## 规则生成与维护

`backend/tools/academic-scoring.cjs`从当前bank/report源码生成私有`backend/academic-scoring.json`和安全公开`js/academic-scoring-meta.js`。私有快照保留60题ID/科目/类型/答案/容差/选项数；公开文件只有上述六键，不含题目或答案键。独立摘要页不加载bank、report或本机库模块，开发API入口不公开后端快照；静态ZIP不包含后端文件。

```powershell
node backend/tools/academic-scoring.cjs
node backend/tools/academic-scoring.cjs --check
node backend/tools/assessment-schema.cjs --check
```

修改题库或报告源码后，先核对题库/规则版本与实际计分变化，再生成、审阅两输出并运行回归；不能仅更新指纹绕过错误。既有assessment-schema仍只输出作答形状，不混入答案键。计分数值转换、ECMAScript空白、进制、IEEE浮点容差及非负Math.round与原浏览器引擎保持对照。

指纹绑定规范ASCII JSON与源文件SHA256；源文本先将CRLF规范为LF，使Windows工作树与Git源码包同规则一致。这是部署规则一致性检查，**不是防篡改签名、历史规则快照认证或教师审校证明**。Python懒加载时检查结构、指纹、当前ID/类型/选项数和有限答案/非负容差；快照缺失、损坏或过深JSON仅使v2返回通用503，不回显内容或影响v1，不静默使用另一套规则。

数据库仍schema5、健康API2，没有新迁移；既有升级前停服务一致私有备份和回退要求不变。具体操作见 [schema5说明](advisor-edit.md#schema5升级与回退)。未部署公司生产或读取真实学生样本。

## 验证与后续

虚构资料覆盖0–15道正确数、数值/容差/进制/负零/极端值与真实Node引擎对照，v1字节保持、v2白名单/指纹/模式、完整0%/100%与未完整null、损坏快照仅阻止v2、权限和原答卷不变。真实浏览器验证29列实际CSV、切回v1、指纹错配及最终核对期间切换模式不下载；桌面与375px已检查。准确数量与下一步见 [台账](progress.md)。探索方向摘要随后独立推进；真实校准、人工审校、模型接入及公司部署仍需后续资料或验证。
