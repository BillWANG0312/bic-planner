# 可选建议草稿与人工确认（v1.6.0）

本阶段完成可替换的文案接口、确定性本地模拟、规则回退和人工选段应用。**默认关闭，没有真实模型适配器、API 密钥、付费调用或向外部发送学生资料。** 不需要新建账号角色或升级数据库；沿用 schema v3 与 API v2。公司批准的服务、数据处理和正式部署仍是外部依赖。

## 操作

1. 主动连接学校账号服务，读取自己的一份服务端报告。题库或院校目录版本变化时，先在本机复核、重新生成并确认更新该报告，再生成建议草稿。
2. 点击「生成建议草稿」并确认。本校服务收到严格的数值/枚举上下文及四段当前建议基线。生成不写报告；当前阶段只显示「规则回退」或明确标注的「本地模拟」。
3. 对照四段原文和新文，勾选实际需要的变更，填写核对人。未变内容不可选；关闭预览不改报告。草稿有效 15 分钟，到期需重新生成。
4. 再次确认应用到所读源修订。服务器只取此前私有保存的草稿，验证所有权、有效期和修订，仅修改勾选的建议文字，并追加修改前后文本、核对人、生成来源和源修订。成绩、答卷、方向排序和原报告编号不变。
5. 应用只更新服务端。本机当前学生及本机归档保持原状；需要在本机查看时，另行确认「打开到本机」，再按需归档/备份。报告正文及 PDF 的当前建议标记区分本地模拟/模型草稿经顾问核对；完整私有审计在编辑面板，不追加到家长摘要或 PDF 附录。

取消不发送应用请求。旧修订或已过期/已应用的草稿拒绝写入，不自动覆盖。网络断开时可能服务器已保存，页面不自动重试；先重新读取服务端报告并核对修改历史。离开面板、切换账号或报告会清预览，迟到响应不能恢复旧内容。关闭的草稿在服务端直到到期才释放配额，不能用关闭预览绕过限制。

核对人是当前报告所有者填写的记录文字，不能代替学校的顾问任命或真实人工审校。student/advisor 仍只能管理自己拥有的报告；跨用户教师分配尚未实现。模型输出即使结构通过，也未认证其建议正确，使用者须逐段阅读。

## 默认与本地演示配置

不设置 `BIC_DRAFT_MODE` 时为 `disabled`，即使主动生成也返回当前四段建议，标记 `kind: rule`、`reason: disabled`，无可应用的变化。超时、忙碌、不可用、生成器异常或输出非法同样保留基线；不得把回退称为真实 AI 生成。此处基线可能已包含顾问编辑，不会重置为早先的系统原文。

在 [账号连接的本地开发环境](cloud-connection.md) 中，可在启动服务前明确设置：

```powershell
$env:BIC_DEV = '1'
$env:BIC_PUBLIC_ORIGIN = 'http://127.0.0.1:9001'
$env:BIC_DRAFT_MODE = 'local_mock'
# 保留此前设置的私有 BIC_DATABASE_PATH，然后启动同源开发入口
python -m backend.bic_api.dev
```

`local_mock` 仅允许显式开发模式和 localhost/127.0.0.1 来源，不可在正式学校来源开启；只是本地固定文案演示。恢复默认时删除该环境变量或设置 `disabled`，重启服务。磁盘前端账号配置仍默认关闭，file:// 无服务请求。

`provider` 模式只提供服务端注入协议，不会从环境变量加载厂商、动态模块、URL 或凭据。当前常规入口未注入供应商，因此返回 `reason: unavailable` 的规则回退。服务工厂支持 `create_app(settings, draft_provider=对象)`；现有供应商测试向草稿服务直接注入纯本地假实现，不进行真实网络调用。

对象提供安全 ASCII 标识 `generator`（1–80 个字母、数字或 `._-`），以及同步方法 `propose(context_dict)`，返回四个纯文本键 `summary/academic/plan/personality`，每段非空、最多 4000 UTF-16 码元。未知字段、非法 Unicode、HTML 执行能力均不接受或不启用；页面把合法的 HTML 形状文字按纯文本显示。

供应商收到的 context 仅包含：

| 字段 | 内容 |
|---|---|
| `status` | `draft` 或 `complete` |
| `direction_id` | 固定专业方向枚举 |
| `personality_complete` / `personality_code` | 完成状态，以及完整画像代码或 null |
| `subjects` | 四科固定枚举、答题数、总题数 15；完整科目才有 0–100 整数百分数 |

姓名、学校、报告编号、逐题答案、自由文字、审核者和现有建议不传给供应商。四段基线仅留在本校服务用于对照和回退。服务不会重新计算成绩或认证浏览器规则结果；已有顾问覆盖的基线必须与服务器保存值完全一致，未编辑段是浏览器按当前题库计算的规则文字。脱去直接标识不等于这些数值可以任意对外分享；未来若增加真实适配器，须先批准数据处理、供应商和费用，并更新用户确认说明后再启用。

## 接口和容量

两个接口均需原有 Cookie、精确 Origin 和当前内存会话的 X-CSRF-Token；只有报告所有者可用，受邀家长账号及只读令牌无权访问。

| 接口 | 请求与响应 |
|---|---|
| `POST /api/reports/{id}/advice-drafts` | `{revision, context, fallback}`；201 返回草稿 ID、报告 ID、源修订、创建/过期时间、kind/generator/reason 及 before/sections |
| `POST /api/reports/{id}/advice-drafts/{draft_id}/apply` | `{sections: 唯一段落名数组, reviewer}`；200 返回原有完整报告结构；真实变更修订加 1 |

应用请求不能提交替换文案或评分。空白首尾差异不算变更；没有实际变化时不写历史、不增修订，并消费该草稿。有效变更不截断已有历史，超过每报告 200 条或完整账号配额时 413，保留旧记录与草稿。旧修订 409 `REVISION`；本人已过期/应用为 409 `DRAFT_EXPIRED/DRAFT_APPLIED`；未知/跨账号为 404；格式为 422。

草稿保存在**单进程内存**，15 分钟、每账号最多 5 份、全进程最多 200 份，创建中的预留也计入。到期在下一次创建/应用时回收；进程重启即丢弃，需要重新生成。只保留有限的已应用/过期状态标记，不保留其文字。最多同时两个 daemon 供应商任务，默认等 5 秒；超时任务仍占槽直到退出，后续返回 busy 回退，不无限开新线程。未来真实适配器仍必须实现自身网络超时、取消/资源控制；不能把 daemon 限额当作可终止任意代码的隔离容器。

应用与生成都复查启用账号和当前报告，落库使用事务内的修订及账号启用校验。旧页、其他设备更新、禁用账号和重复应用不能越过这些边界。多 worker 会拥有不同私有草稿和限额，当前部署方案保持单进程，不能直接增加 workers 声称功能等效。

私有历史可选 `origin` 固定包含 `kind/draft_id/generator/source_revision`，旧备份没有此字段仍兼容；合法来源随备份、恢复和重新生成保留。之后手工编辑/恢复创建的新历史不冒用生成来源。导入资料和核对人文字是用户提供的记录，不是供应商签名或不可篡改审计证明。公开家长摘要不含这份私有历史，公开的最终建议仍由所有者预览确认分享。

## 验证与后续

本地测试覆盖默认关闭、四段严格上下文、供应商仅收数字枚举、异常/超时/满槽回退、私有容量与到期、所有权/CSRF、并发修订和重复应用、禁用账号竞态、原成绩不变、部分选段、来源备份兼容及打印标记。真实 Chromium→FastAPI/SQLite 使用虚构账号和 local_mock，验证生成不写、取消不写、人审后选段落库、另设备变更不覆盖、本机不自动改变、打开与归档保留来源。具体最终数量和日志见 [台账](progress.md)。

没有真实模型请求、外部模型质量评估、公司部署或教师语义审校。下一阶段为明确选择的匿名统计与校准工具；模拟样本只能验证工具行为，不能宣称真实学生样本校准完成。
