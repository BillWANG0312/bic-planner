# 指定顾问的单报告只读授权（v1.10.0 / schema4）

默认没有跨用户报告权限。`advisor`角色名称不授予全校读取权；只有报告所有者明确选择既有顾问账号并确认完整资料范围，接收者才可通过独立入口读取这一修订。**本轮仅实现只读，不提供顾问修改、删除、转授或批量导出原报告。** 公司生产环境尚未部署。

## 所有者授权

1. 主动连接账号服务，读取自己的一份服务端报告。
2. 在「指定顾问的完整报告只读授权」填写学校已创建的顾问账号，选择24小时、3天或7天。系统不创建账号、不发送邀请消息或读取全校账号名单。
3. 点击预览，核对姓名、报告编号、题库/目录版本、源修订、接收账号、期限和完整资料范围：**姓名、逐题答卷、版本、顾问建议/修改历史及授权者账号**。这比家长摘要范围更大，不能把普通分享链接或批注邀请当作顾问授权。
4. 再次确认后才创建。更改接收账号、期限或报告会使旧预览失效。有效的同报告/同修订/同接收人重复授权返回409，不额外消耗配额；网络结果不确定时先读取授权历史，不自动重试。
5. 可随时查看历史并撤销，撤销幂等。每报告最多10份、每账号作为创建或接收共100份历史，包含过期/撤销/源变化，不静默删记录腾额度。需要扩容或历史归档时另行设计。

授权绑定**创建时报告修订**，数据库不复制答卷。所有者更新任何报告内容导致修订递增后，旧授权变为`source_changed`，新的读取立即拒绝；顾问不能自动读取未经重新确认的新资料。所有者复核更新后的报告，再明确授予新修订。删除原报告会删除关联顾问授权，原家长分享/批注级联行为不变；界面删除确认已说明。

## 顾问读取

从学校同源HTTPS网址打开`teacher.html`，主动连接、登录顾问账号、刷新有效授权名单，再选择一份报告读取。打开页面、连接或登录均不自动读取学生名单/答卷。页面不加载测评主控或本机库，不访问localStorage/sessionStorage，没有编辑、上传、打开到本机、归档或PDF按钮。

原始归档在内存严格校验后生成只读视图，并另外展示纯文本顾问修改历史。题库/目录版本不明或与当前不符时拒绝规则视图、清正文，提示所有者复核更新后重授。即使版本相同，视图仍是按当前同版本本地规则生成，不是原历史PDF或不可变规则快照；原报告数据没有改写。

每次读取在服务器同时检查双方账号启用、接收人仍为advisor、报告归属、修订、期限和撤销状态。其他顾问、普通学生、家长邀请和匿名只读令牌不能读取。原owner CRUD/分享/批注授权/文案应用接口仍只认原所有者，顾问只读接口不开放写入。

本地到期计时会清详情；刷新名单发现授权失效，或重新读取失败，也会清正文和私有历史。切换账号、断开或离开页面清名单/报告，迟到响应不能恢复旧账号资料。多标签Cookie变化会因内存CSRF不匹配被拒绝，不能在旧账号名下显示另一账号内容。没有后台轮询，请主动刷新核对；服务器校验是新读取的依据。

**只读限制针对原报告的服务端写权限。已经读取、复制、打印或截图的资料无法收回，也不能靠撤销远程删除副本。** 用户仍需按学校规则保管所读学生资料，不能把没有内置导出按钮当作防复制保证。

## API

沿用API v2健康接口、Cookie、精确Origin、写请求CSRF及浏览器认证读取的内存CSRF绑定。前后端须一起更新；旧服务器不会提供新增路由。响应均no-store/no-referrer/noindex。

| 方法 | 地址与含义 |
|---|---|
| POST | `/api/reports/{id}/teacher-access`；`{revision,recipient_username,ttl_hours,scope:"full_report_read_only"}`，201返回元数据 |
| GET | `/api/reports/{id}/teacher-access`；所有者读取本报告授权历史 |
| DELETE | `/api/reports/{id}/teacher-access/{grant_id}`；所有者撤销，204 |
| GET | `/api/teacher-access`；当前指定顾问仅列有效授权 |
| GET | `/api/teacher-access/{grant_id}`；仅指定顾问读取`{grant,report}`，其中report为原完整报告结构 |

元数据固定包括授权/报告ID、源修订、姓名/原编号、授权者/接收账号、只读scope、创建/过期/撤销时间和状态。所有者可见active/revoked/expired/unavailable/source_changed；顾问名单只有active。详情单次JOIN同时取权限条件与同一份正文，严格验证归档及存储元数据；损坏返回通用503，不回显私文。名单和撤销不读取答卷正文。

未知/跨账号/失效404，旧修订409 REVISION，有效重复409 DUPLICATE，配额413，未知scope/多余字段/类型错误422。禁止把角色名称、家长令牌、客户端owner参数或缓存名单当作授权。

## schema4升级与回退

新版在**任何会初始化数据库的入口**（包括API、开发入口或账号CLI）首次打开已知精确schema v1/v2/v3时，事务追加缺少的分享/批注/teacher_grants结构，最后升至4；新库直接为4。迁移不重建旧用户表、密码哈希、会话、报告JSON/修订、分享令牌摘要、家长邀请或批注正文。任一步失败全部回滚；未知/修改结构及未来版本拒绝，不清库。

升级前由维护者停止所有使用该库的进程，在实际网站文档根目录外做完整私有一致备份并保存匹配旧源码。不要在线只复制主文件就假定一致，也不要手工修改user_version绕过检查。然后更新前后端，在私有环境启动并核对账号、已有报告、分享/批注、顾问授权与访问边界。当前仍是单进程方案，登录/读取容量和可信代理依赖没有因此自动解决。

旧程序不能直接打开schema4。若需回退，先停止新程序并保留新库，再恢复与旧代码匹配的升级前私有备份；评估备份之后的新报告/授权/批注损失，不覆盖唯一新库。迁移不等于公司生产部署，本次没有公司服务器、真实账号或生产数据库访问。
