## 合并后首次复现（历史记录）

1. 新前端真实ReportStore归档喂给当前Python ArchiveRecord，因新规划字段和30个对象型性格答案被拒绝。现有严格接口没有静默接纳或截断新资料，新报告上传会失败。
2. 旧合法完整备份进入新ReportStore.previewImport，会报未支持的规划字段；仅保留年级和旧24个数字性格答案仍报「性格题1答案无效」。不能把旧云报告/备份导入正常视作已验证。
3. 同一旧完整样本在旧引擎为complete，换新引擎成为draft，规划与性格分母改变。摘要v1/v2/v3仍保留14/13/24，必须区分合同，不能修改旧格式的字段含义来适配新问卷。
4. app.js把旧数字性格答案按位置包装为新特质答案，并标legacy；report.js的特质计算不据该标志隔离含义。旧24题与新30题不是位置等价，不能以这种方式迁移或给旧答案赋予新特质解释。旧schoolSubjects也不再按原方式进入规划重算。
5. `node backend/tools/assessment-schema.cjs --check`遇game题调用不存在的source()而报TypeError；preference-schema.cjs找不到原preferredMajor题，按合同保护拒绝；academic-scoring.cjs因report.js源文本变化而指纹陈旧。学术题库和evaluateAnswer/gradeAcademic核心逐字未改，学术60题实测同分；另外两份合同须先设计兼容，不能只重生成文件让检查变绿。

实际合并后完整回归日志保留`password-post-main-{frontend,backend,api-integration}-full.log`；密码模块另有在该main上的定向通过日志。完整失败数及本阶段边界见 [持续台账](progress.md)。首次前端整套因旧夹具初始化失败遗留HTTP服务而挂住，保留interrupted日志；已用5个子进程回归最小修复测试资源清理，再重跑获取完整结果。没有删测试、放松业务断言/后端校验、覆盖他人功能或把中断/失败记成成功。
