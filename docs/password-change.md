# 本人改密与全部会话撤销（v1.15.0）

从主页「账号报告服务」点击「账号安全：修改本人密码」，或打开同源`account.html`。本页默认不联网；主动连接学校服务后恢复本人会话，或登录学校提供的账号。当前只做本人改密，未实现忘记密码、管理员重置、邮件/短信或公开注册。

## 操作

1. 核对当前本人账号，输入当前密码、新密码和再次输入新密码。
2. 新旧密码须不同，两次新密码一致；密码长度为12–128个Unicode码点，新密码不能全空白。不修剪或规范化口令中的空格、大小写或Unicode。
3. 点击修改后确认「修改密码并撤销该账号所有设备的全部会话」。取消会清空三项输入，不发改密请求；输入或页面身份在确认期间变化也取消旧提交。
4. 发送前清空输入，只提交一次。收到成功204后，本页断开，所有设备须用新密码主动重新登录，没有自动登录或重试。

成功不会修改姓名、角色、原报告/修订、家长分享/邀请、顾问只读/编辑授权或审计，也不会撤销其他账号的会话。既有分享令牌按原期限/撤销规则继续有效，不把改密当作撤销已发分享的替代操作。已经复制/下载的内容无法收回。

所有会话在服务器事务提交时撤销；其他已打开页面在下一次认证请求时拒绝旧会话并清旧私密视图，没有新增后台轮询或远程擦除。已经完成授权检查的在途请求可能完成，不宣称能撤回它们。本页断开只清本页内存；普通「退出当前会话」仍只注销当前会话，改密成功才撤销全部本人会话。

## 未确认结果

网络中断、超时或不符合协议的成功响应可能发生在服务器已经改密之后。本页清口令并断开，显示结果尚未确认，不宣称「没有修改」或自动重传。先主动用新密码登录核对；若重新连接恢复了已有Cookie会话，先点击退出当前会话再登录，新会话恢复本身不证明新密码有效。若新密码未成功，再由本人主动尝试旧密码。系统不自动轮试，两次尝试同样计入限流。

旧密码不正确、会话失效、限流或参数错误均不会返回成功。错误不会回显口令/哈希，页面不把这些响应当作改密成功。只收到认证错误不能据此证明所有设备已退出；服务器状态以实际事务及后续明确登录核对为准。离开、取消、断开、退出或本地期限到达会清密码输入，晚响应不能恢复离开的页面或清除后来明确建立的会话。

## API与事务

`POST /api/auth/password`仅接收严格JSON对象：

```json
{"current_password":"<当前口令>","new_password":"<新口令>"}
```

需要当前HttpOnly会话、匹配页面的`X-CSRF-Token`和配置的同源Origin。不能指定其他username/user_id、角色或凭据版本。成功204空体，按相同Cookie路径及Secure/HttpOnly/SameSite设置删除当前Cookie，不返回新会话。新字段是增量接口，健康API仍2。

服务重读本人启用状态，核对旧Argon2密码，并计入与登录共享的每账号5次/分钟和实际来源IP20次/分钟预算；不信任转发头。密码哈希/验证沿用全局两个并发资源槽，繁忙或限流429携Retry-After。边界格式非法422、旧密码/会话失效401、Origin/CSRF错误403、存储故障503；输入验证错误体不含原始参数。

哈希计算完成后，SQLite `BEGIN IMMEDIATE`单事务重新核对当前token哈希、CSRF、期限、账号启用/归属与刚验证过的原password_hash，再CAS更新为新Argon2哈希并删除本人全部sessions。并发另一改密、注销、禁用、到期或原哈希变化都不能继续提交；更新或删除异常整体回滚，不会部分改密/部分撤会话。原哈希不在API中暴露。

登录也在创建会话事务内检查被验证的原哈希。登录先提交，其会话会被随后的改密删除；改密先提交，仍在验证旧哈希的登录不能再创建有效会话。此检查不改变报告/授权表或其他用户。

## 密码长度与页面边界

后端创建/登录一直按Python字符串长度判断12–128码点。客户端登录与改密现按同一口径，并拒绝无法编码为UTF-8的孤立代理项。既有五个登录入口及新页面的密码输入最多容纳256个UTF-16码元，因此128个非BMP字符可以设置并从原入口登录；API上限仍128码点，其他文本/存储上限不变。

本页只加载cloud-config、cloud-client和account三个脚本，不加载题库、报告、专业/规划引擎或本机库。不读取/写入localStorage、sessionStorage或报告备份，不记录口令日志；口令只在输入/本次请求内存中使用。默认配置关闭，file://本机模式不能连接；正式使用仍需学校批准的同源HTTPS服务。375px页面可用。

schema仍5，没有新增表或本轮迁移。任何新版初始化入口（含账号CLI）前仍须停全部相关服务，在网站根目录外做私有一致备份并保存匹配源码；回退先保留新库再恢复匹配旧代码备份，不手改版本，详见 [schema5升级说明](advisor-edit.md#schema5升级与回退)。

验证只用虚构账号/报告与本地SQLite：多会话全撤、其他用户/报告/授权/审计保留、Unicode、并发与触发器回滚、共享限流/哈希资源、严格API、确认取消/变更/到期/离开、真实浏览器已落库丢响应不重试、旧会话跨页失效与旧入口新密码登录。独立审查及准确数量见 [持续台账](progress.md)。没有访问公司真实账号、发送消息或部署生产。

本阶段已从合并后的main另建分支，密码模块定向验证通过；当前全站存在独立的 [新版测评兼容问题](upstream-assessment-compatibility.md)，未提供全站静态发布验证保证。本轮交付源码和改密补丁，整体失败日志与准确结果随包保留。
