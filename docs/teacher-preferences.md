# 学生自选专业意向与地区偏好摘要v3（v1.14.0）

`teacher-summary.html`增加默认未勾选的「附加学生自选专业意向与地区偏好」。这是带姓名和报告编号的私密校内清单；只反映学生原来明确选择的固定选项，不是系统推荐、人格类型、适合度、录取预测、真实校准或匿名资料。逐份选择1–20个现有有效完整报告只读授权，操作权限沿用 [完成度清单](teacher-summary.md)，不增加全校访问或编辑权限。

## 模式和操作

| 学科表现 | 学生自选偏好 | 格式 / CSV列数 | 文件名 |
|---|---|---|---|
| 关闭 | 关闭 | 原v1 / 21 | `bic-teacher-completion-v1.csv` |
| 开启 | 关闭 | 原v2 / 29 | `bic-teacher-academic-v2.csv` |
| 关闭 | 开启 | v3 / 27 | `bic-teacher-preferences-v3.csv` |
| 开启 | 开启 | v3 / 35 | `bic-teacher-academic-preferences-v3.csv` |

两个选项独立且默认关闭，原v1/v2结构、列、计分口径和文件名保持。主动连接、登录、刷新并逐份选择授权，再勾选所需扩展。预览核对表格和选项版本/指纹后确认导出。模式或选择变化会清除旧预览；不能用已核对的v1/v2直接下载另一模式。

v3在所选的21列或29列后追加六列：专业意向作答、专业意向（学生自选，非推荐）、地区偏好作答、地区偏好（学生自选，多选）、偏好选项版本、偏好选项指纹。预览和CSV共用映射；文本字段保留BOM、CRLF、引号与公式前缀保护。表格可左右滚动，移动页面不横向溢出。

## 选项口径

只投影规划中的`preferredMajor`和`countries`，分别最多2选、3选。专业意向采用原来的12个兴趣选项，不能误用14个推荐专业目录；地区采用原来的8个选项。中文标签直接来自当前题目，没有新推断或自由文本。多选按原字典顺序显示，以「；」分隔，顺序不代表优先级。

缺省或明确空数组都显示「未回答」，API为`{answered:false,choices:[]}`。非空为已回答；「还不确定」「还没想好」是有效明确回答，可与具体选项并存，不能强行归到某个专业/地区或算作缺答。部分规划可以显示已答的这两题，不要求整份规划完成；不输出规则推荐、MBTI类型、自填学校科目、顾问建议、原始答卷或完整审计。

须当前题库2026.10。此功能不使用专业排序或院校规则，因此旧/缺省院校目录仍可保留其原记录，不借此认证历史规则。若另勾学科表现，学科完整度、null/0%和规则指纹仍按 [学科表现v2](teacher-academic.md) 的独立口径。

## 接口与字典

`POST /api/teacher-summaries`在既有`grant_ids`、`academic`之外增加严格布尔`preferences`。缺省/false保持原v1/v2，请求端不发送false字段；true才得到version3。v3顶层增加精确的`options:{academic:boolean,preferences:true}`和`preference_schema`四键元数据，每个report只增加上述两题的`preferences`。只有academic=true才有原scoring/performance，不为偏好模式加载评分文件。请求的额外字段、非布尔及重复/超量授权ID拒绝；所选授权ID可按任意明确顺序提交，响应必须保持同序。后端将原作答选项按字典规范排序；浏览器拒绝响应中未知/重复/超量/乱序的选项ID，以及声明与内容不一致。两题均属规划必答，其作答状态还须与必答完成数相容。

元数据为bank_version、schema_version（`planning-preferences-v1`）、schema_fingerprint和basis（`explicit_student_choices`）。公开`js/preference-schema.js`只含这四键和两组固定id/label/max，不含学生或推荐规则。私有`backend/preference-schema.json`同时绑定majors/plan源码SHA256；源文本CRLF先规范为LF，再对递归排序的UTF-8 JSON生成指纹。两端必须同时部署。指纹用于检查部署一致性，不是防篡改签名、历史选项认证或人工审校证明。

```powershell
node backend/tools/preference-schema.cjs
node backend/tools/preference-schema.cjs --check
node backend/tools/academic-scoring.cjs --check
node backend/tools/assessment-schema.cjs --check
```

选项更新后先核对版本、原题目和语义，再生成、审阅两文件并回归，不能只改指纹绕过问题。后端懒加载严格校验大小、结构、重复键、指纹、当前题库ID/max及文本；缺失/损坏/过深文件只使v3返回通用503，原v1/v2仍可用。评分文件坏掉不阻止纯偏好v3。

## 授权、新鲜度和资料保管

服务端仍用同一条JOIN核对整批授权、双方启用、接收顾问角色、归属、源修订、期限与撤销；任一失效整批拒绝，没有部分行。所有者新授权预览/确认已说明可保存这些必要摘要，完整只读授权原有读取/复制范围不扩大。编辑授权、家长令牌/批注和advisor角色本身不能访问清单。

导出前及确认后用同一批ID和相同两选项再次读取，比较完整payload与页面身份/模式/期限/版本/指纹。变化、网络/协议错误、撤权或到期都停止旧下载；不自动重试、抓取全校、改用完整答卷或静默降级。程序在最终读取期间改变选项也不能导出旧文件。断开、退出、换账号或离开清内存，迟到响应不能恢复；已经复制或下载的副本无法收回。

摘要页仅加载安全字典/元数据与连接/摘要模块，不接收原答案或完整审计，不加载题库/报告/本机库，不访问浏览器存储。没有新表、缓存、迁移、统计收集、新增答卷/成绩上传或外部模型调用；显式摘要POST仅发送所选授权ID和模式，原报告和修订不变。schema5、健康API2保持；既有任何初始化入口前停服务、私有一致备份和匹配旧代码回退要求不变。

验证仅使用虚构报告：四种模式、缺答/unsure/多选、原格式字节、严格字典、坏依赖隔离、权限与原JSON不变；真实Chromium→本地FastAPI/SQLite核对27/35列实际CSV、错配指纹、最终切换和确认框期间撤权。没有真实样本或正式部署。准确测试结果、剩余公司环境/人工审校依赖及下一步见 [台账](progress.md)。
