# 本机报告库

本阶段在原有单学生进度之外，新增同一浏览器的多报告管理。仍是纯静态网站，不需要账号、数据库或 API 密钥；也不具备多用户教师后台、自动云端同步与学生权限隔离。

当前分为原14道规划/24道数字量表与新游戏/30题特质两个profile；JSON v1/v2、原始续答保护与未适配入口见 [测评版本说明](assessment-profiles.md)。原CSV仅支持纯旧库，新或混合库请保存JSON。

## 操作

1. 完成测评或生成探索草稿后，在报告页点击「归档报告」。当前学生的作答、报告编号/日期及顾问修改会保存到本机报告库。
2. 从首页或报告页打开「本机报告库」，按姓名或报告编号搜索，查看完成度与当前规则下的专业方向。
3. 打开归档会替换当前作答和报告；只填写了年级/目标年份也算当前进度，需要明确确认。可以取消，先归档或导出当前报告 PDF。
4. 同一报告再次归档会先确认更新已有归档。删除只删除选中的归档，当前打开的作答不受影响；删除前建议导出备份。
5. 「导出 JSON 备份」保留已归档报告的作答、顾问建议和修改历史。它不自动包含尚未归档的当前作答。可以在其他浏览器打开本系统后手动导入，不能称为自动跨设备同步。
6. 导入 JSON 后先查看数量和重复预览；默认跳过已有编号。只有明确勾选替换重复归档并确认导入，才会覆盖旧归档。未确认时不修改报告库。
7. 「导出 CSV 汇总」用于查看姓名、年级、目标入学、测评完成度、完成科目的分数和探索专业等。CSV 不包含完整答卷与顾问历史，不能代替 JSON 备份。

备份含学生姓名与作答，请在有权限的设备和位置妥善保管。共用同一浏览器/网站地址的人可以访问同一报告库；本地模式不提供账号权限隔离。清理浏览器数据可能同时删除当前进度与报告库。

## 报告版本

归档保存作答和顾问记录，不把题目与院校目录重复存进每份归档。打开时按相应profile引擎、共享当前学术题库和院校资料重新生成，保留原报告编号、日期、顾问修改及来源记录；版本不同时显示并确认提醒。若需保存当时的原始版式与建议结果，请另存原始 PDF。

对未完成答卷，CSV 将未完成科目的分数字段留空，不把未答当作能力零分；性格未完成或维度均衡时保留相应状态。

## 数据边界与恢复

- 上限：100 份归档，完整序列化库/导入文件最多 2,000,000 个 UTF-16 码元；每份最多 200 条顾问历史，建议与前后文字每项最多 4,000 字。浏览器还可能有更小的实际存储配额。
- 导入整批校验版本、字段、题目/选项标识、数值范围、日期、重复编号及容量。任何一份错误会拒绝整个批次，不保留一个已导入一半的库。
- 保存、导入和删除只在完成校验后一次写入库；配额/权限失败时原有归档不变。打开归档时若当前进度无法写入，当前学生的内存与持久化进度也不替换。
- 损坏或不兼容的旧库阻止修改、导入和覆盖，提供「下载原始数据备份」，不会自动清空。原始数据备份是恢复线索，不代表数据已经修复。
- 不支持的旧题目/选项标识不会被静默删掉；需保留原始备份并使用兼容版本或后续迁移工具处理。
- CSV 为 UTF-8 BOM，引用逗号、引号与换行；公式形状的姓名等文字以文本方式转义，避免在表格软件中直接执行。

## 实现与验证

`js/report-store.js` 负责归档模型、严格校验与持久化；`js/report-library.js` 负责列表、确认、导入预览与文件下载；`js/app.js` 负责当前学生的页面与安全切换。报告内容在进入报告页时与最新作答核对，避免可见姓名与实际归档学生不一致。

回归覆盖归档/更新、JSON 往返、CSV 文件字节、批次拒绝、重复处理、损坏恢复、配额、跨页与刷新、自由科目文字、顾问来源、版本提醒、手机布局和离线 file:// 流程。库操作不增加网络上传。
