# 学校账号批注（v1.5.0）

当前测评范围：本页报告操作沿用旧版14道规划/24道数字量表合同；新版游戏/30题特质尚未适配，明确拒绝进入旧云端或投影，不截断或混用分母。新旧档案与续答操作见 [测评版本说明](assessment-profiles.md)。

批注使用学校已创建的账号和单报告邀请，不接受匿名写入。普通 share.html 只读链接没有批注权限。默认账号连接仍关闭，本段仅做本地实现/验证，没有部署公司服务器或向家长发送消息。

## 报告所有者

1. 主动登录账号服务，读取要讨论的服务端报告。在「邀请家长批注」输入学校提供的完整接收账号，预览固定摘要并选择24小时、3天或7天期限。
2. 核对学生、接收账号、源报告修订与摘要后确认。接收账号必须已存在、启用且不是本人；系统不自动建账号、不发消息。原修订已变化则要求重读，不自动换新修订邀请。
3. 自行告知对方从同一网站的 family.html 登录。账号由有权限的操作员交互创建，命令见 [后端说明](backend.md)。本阶段复用现有普通账号，授权来自单份邀请，不给全校或原始答卷权限。
4. 所有者也可从家校批注页面打开对应讨论并回复。每个接收账号有单独线程，其他受邀账号看不到这段讨论。
5. 「查看批注邀请」可撤销授权。对方之后不可读取或追加，所有者仍可读历史但不能继续追加。报告更新不改旧邀请摘要；需要讨论新版本时另行预览邀请。

批注邀请与匿名只读分享是两份独立权限，期限和撤销分别管理。撤销其中一份不会替代另一份。删除原报告则会使所有相关分享/邀请失效，并删除关联批注记录，删除确认会明确告知。

## 受邀账号

进入 family.html，点击连接并登录学校账号，再主动刷新邀请名单，点击一份邀请读取固定摘要和讨论。页面不访问本机测评进度、报告库或浏览器存储。口令提交后清空，所有读取和写入都绑定当前 Cookie 与内存 CSRF，另一标签换账号后会拒绝旧页面请求。

批注是纯文本、仅追加，不修改成绩、规则建议或顾问编辑审计；当前不提供修改/删除单条批注。每条最多1000个 UTF-16码元，正文需非空，每线程最多100条。写入按账号每分钟最多10次；完全相同的成功请求重放不重复写或扣写入配额。

断线可能发生在服务器已保存之后。页面保留本页文字和请求号，不自动重发，请先刷新讨论核对；如果已找到对应回执会确认已保存。确认旧文字不会清掉后来新写的草稿。临时刷新失败保留可见、可恢复的草稿。刷新名单确认邀请失效时，摘要和讨论会清除；自己未提交文字只保留为只读可复制，不能继续发送。离开、切换讨论、断开或退出有未提交/待确认文字会要求明确放弃；刷新/关闭浏览器仍可能丢失仅存本页的文字，应先复制留存。账号改变时清理私密内容，不能带到新账号。

保存后的批注与固定摘要一同用于家校沟通，不是正式成绩或录取认证。撤销权限不能收回别人已经读取、复制或截图的内容。

## 范围和接口

每报告最多10份邀请，每账号作为创建者或接收者最多参与100份，**包括过期/撤销历史**。不为腾配额静默清理批注；扩容或明确归档需后续设计。到期、撤销或任一参与账号禁用后停止新追加；接收人不可读，所有者可读自己报告的历史。达到100条的有效线程仍可读但不能追加。

| 接口 | 权限/用途 |
|---|---|
| `POST /api/reports/{id}/parent-access` | 所有者；`revision,recipient_username,ttl_hours,content`，预览修订绑定的独立摘要邀请 |
| `GET /api/reports/{id}/parent-access` | 所有者查看该报告邀请元数据 |
| `DELETE /api/reports/{id}/parent-access/{grant_id}` | 所有者撤销邀请，历史保留 |
| `GET /api/parent-access` | 当前账号创建的邀请及其仍有效的受邀记录，没有其他人的名单 |
| `GET /api/parent-access/{id}` | 所有者或有效接收账号；严格摘要、该线程批注及当前可追加状态 |
| `POST /api/parent-access/{id}/comments` | 有效参与者；`body,client_request_id`，仅追加 |

写操作需精确 Origin 和 CSRF；认证读取也使用私有 CSRF 绑定当前账号。UUID 请求号只用于幂等，不是访问凭据。同账号同线程同 UUID/同文字返回原记录，不同文字稳定409，不绕过撤销/到期；不同线程或账号不能读取该记录。批注返回角色标签，不暴露其他用户ID、密码、会话或原答卷。

## 升级与本地运行

**升级前停服务，并在站点外做完整私有备份。** 精确已知 schema v1/v2 在单事务中升至 v3：补充邀请/批注表和索引，不重建用户表或角色，不改原密码哈希、会话、报告与匿名分享。任何失败回滚，未知或篡改结构仍拒绝。旧程序不能直接读取 v3；降级前保留新库，再恢复匹配的原备份，评估升级后的新增记录损失，不直接覆盖。

本地 `python -m backend.bic_api.dev` 同源提供 family.html；正式需同时发布该页面、css/family.css、js/family.js 与最新客户端/API。沿原 [连接配置](cloud-connection.md) 使用 HTTPS、同源 API 和正确 Cookie 路径，默认开关不变。反代不得记录 Cookie、CSRF、登录/评论正文；运维备份和磁盘权限涵盖新增的邀请及批注。单进程限流、可信代理与实际容量仍待公司环境验证。

`pnpm test` 验证客户端和模拟服务的 Chromium UI；Python `pytest backend/tests` 覆盖迁移、权限和并发幂等；`pnpm run test:cloud` 用临时虚构账号验证真实创建邀请、家长提问、断线确认后保留新草稿、管理者回复、撤销和历史保留。人工题库审校、教师跨用户分配、改密找回、公司正式部署和真实样本校准尚未完成。
